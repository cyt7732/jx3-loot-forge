## 6. P0/P1/P2/P3 详述

### P0-01：catalog 初始化失败覆盖 localStorage

- **现象**：组件先创建默认 workspace；catalog、override 或 IndexedDB 初始化进入 catch 后仍设置 hydrated，另一个 effect 仅看 hydrated 就保存。
- **影响**：已有合法 workspace 可能被默认 workspace 覆盖；错误 toast 不能证明用户看到了持久化内容已经变化。
- **证据**：初始默认值见 [LootForgeApp.tsx#L187](../web/src/ui/LootForgeApp.tsx#L187)；失败与 hydrated 见 [LootForgeApp.tsx#L217-L264](../web/src/ui/LootForgeApp.tsx#L217)；读取和同步保存见 [workspace.ts#L7-L21](../web/src/storage/workspace.ts#L7)。
- **建议**：分离 catalogReady、workspaceLoaded、persistenceEnabled；失败只读降级，保存原始 localStorage 字节，提供重试/恢复/另存默认动作，禁止静默覆盖。
- **验收**：故障注入 catalog/override/IndexedDB 初始化，预置可识别字节；失败渲染后 key 字节完全不变且无 setItem，正常启动、坏 JSON、quota/security 异常均有测试。

### P0-02：默认项移除后隐藏但仍导出

- **现象**：初始 workspace 写入 21 项保护、19 项默认出售的 itemStates、customItems、customOverrides；buildCatalogItems 又补入不在 catalog 的默认项，sources=[]。移除 custom 标志后 state 和导出仍保留，零来源项不出现在任何范围。
- **影响**：用户点击移除/恢复后看不到项目，却仍导出自动出售；0 范围、254 个官方 map、981 个官方 boss 都不可见，形成状态与界面不一致的孤儿记录。
- **证据**：状态与 seed 见 [state.ts#L47-L100](../web/src/domain/state.ts#L47)；补入目录见 [catalog/index.ts#L65-L91](../web/src/catalog/index.ts#L65)；合并和范围判断见 [LootForgeApp.tsx#L306-L351](../web/src/ui/LootForgeApp.tsx#L306)、[LootForgeApp.tsx#L408-L414](../web/src/ui/LootForgeApp.tsx#L408)；移除逻辑和文案见 [LootForgeApp.tsx#L712-L721](../web/src/ui/LootForgeApp.tsx#L712)、[LootForgeApp.tsx#L1281-L1293](../web/src/ui/LootForgeApp.tsx#L1281)；CustomItem 不含初始化写入的 category/note，见 [types.ts#L127-L131](../web/src/domain/types.ts#L127)。
- **建议**：拆成“恢复官方管理”和“彻底移除并停止导出”。前者保留可见的官方/系统默认项，后者同时删除 itemStates、customItems、customOverrides；零来源项进入无来源/系统默认或 historical 分组，seed 必须尊重删除，未消费字段须补类型和 UI 或删除。
- **验收**：对 19+21 项分别测试两种语义、刷新、重载、导入、导出；停止导出后 3 张目标表均无该项，恢复官方管理后仍可找到；所有 scope 不得出现状态存在但列表不可见。

### P1-01：导出固定写入未受管的 Doodad/拾取偏好

- **现象**：PICKUP_SETTINGS 除受管的跳过拾取路径外固定输出 23 项 Doodad/拾取偏好；导入只读取 3 条受管路径，其余进入 ignoredFields。
- **影响**：已有配置导入后再导出，即使用户未修改，也可能被固定模板重置未受管偏好。
- **证据**：固定集合见 [exporter.ts#L18-L43](../web/src/config/exporter.ts#L18)；写入见 [exporter.ts#L83-L100](../web/src/config/exporter.ts#L83)；导入忽略见 [importer.ts#L45-L65](../web/src/config/importer.ts#L45)。
- **建议**：默认只写 3 个受管路径和必要 enable；完整模板为显式高级选项，保留未受管字段或提示覆盖；导入/导出共用一份受管路径白名单。
- **验收**：黄金测试断言最小导出路径精确等于白名单；含 23 项旧配置重导不重置其值；合一、仅拾取、仅出售均通过路径集合和字节稳定性测试。

### P1-02：批量/预设直接提交，撤销仅内存单步

- **现象**：分类批量和范围预设计算 preview 后直接 commitStateMap；lowerLevels 会对大量历史装备自动出售，undoWorkspace 只在内存保存一次。
- **影响**：误选范围可一次改动大量物品；刷新或关闭后无法恢复，也没有可审计的前后状态。
- **证据**：批量动作见 [LootForgeApp.tsx#L594-L680](../web/src/ui/LootForgeApp.tsx#L594)；内存撤销见 [LootForgeApp.tsx#L470-L473](../web/src/ui/LootForgeApp.tsx#L470)。
- **建议**：超过阈值先展示 diff、数量、范围和冲突并显式确认，lowerLevels 单独标危险；持久化前后状态、范围、时间和版本，支持刷新后撤销/重做。
- **验收**：超过 20 项取消不改变 workspace；确认页显示各状态增减和冲突数；刷新后仍可撤销，farming、clear、lowerLevels、分类和导入均有回滚测试。

### P1-03：发布与文档版本漂移

- **现象**：package.json 是 1.0.3，package-lock 顶层/根包是 0.2.0；业务源码相对 v1.0.2 零变更却把既有 customItems 行为写成新增；README 写“76 项全覆盖”、保留 v1.0.0 指纹，HANDOFF 停在 v0.2.1/未发布，丝路风雨与丝路风语不一致。
- **影响**：用户、维护者和发布工具无法判断实际变更，反馈时版本指纹和数据名称可能互相矛盾。
- **证据**：版本字段见 [package.json#L1-L4](../web/package.json#L1)、[package-lock.json#L1-L8](../web/package-lock.json#L1)；README 相关表述见 [README.md#L110](../README.md#L110)、[README.md#L121](../README.md#L121)；历史状态见 [HANDOFF.md#L40-L56](HANDOFF.md#L40)。
- **建议**：建立单一版本源；CI 同时检查 package、VERSION、manifest、catalogVersion/hash、README、UI 和 changelog，发布前生成 v1.0.2→v1.0.3 差异清单并确认命名。
- **验收**：版本修改后所有 metadata、指纹、README、离线页一致；不得残留旧版本示例、未发布状态或未经确认的双名称。

### P1-04：workspace 持久化鲁棒性不足

- **现象**：坏 JSON 或校验失败静默回退默认 workspace；同步 save 没有 quota/security 处理；filters、UI、custom、favorites 等校验过宽，缺少 schema 版本、迁移和原始隔离。
- **影响**：用户可能在无提示的情况下丢失配置，浏览器存储异常可能中断交互；未来字段变化难以安全迁移。
- **证据**：读取/默认回退和保存见 [workspace.ts#L7-L21](../web/src/storage/workspace.ts#L7)；大小和解析入口见 [workspace.ts#L34-L38](../web/src/storage/workspace.ts#L34)；宽松校验见 [workspace.ts#L41-L75](../web/src/storage/workspace.ts#L41)。
- **建议**：引入 schemaVersion/migration，坏数据 quarantine 并保留 raw，保存改为 debounce 且捕获 quota/security 错误，界面明确提示并提供恢复导出。
- **验收**：旧 schema、未知字段、截断 JSON、重复 ID、损坏日志都能迁移或隔离；保存失败不覆盖有效 workspace，用户可看到错误且当前内存状态不丢。

### P1-05：测试覆盖缺口

- **现象**：76 个测试集中于 domain/config/catalog/classification；缺少 UI DOM、storage 故障注入、online/offline E2E、离线文件冒烟、危险操作回归和覆盖率门槛。
- **影响**：P0 覆盖、批量确认、刷新撤销、隐藏导出和真实浏览器路径容易回归而不被门禁发现。
- **证据**：测试入口和脚本见 [package.json#L13-L18](../web/package.json#L13)；配置单测示例见 [config.test.ts#L25-L48](../web/tests/config.test.ts#L25)。
- **建议**：用 Vitest DOM 覆盖状态机和存储故障，用 Playwright 覆盖 online/offline、导入导出和危险动作，加入覆盖率阈值及真实文件 GBK 冒烟。
- **验收**：测试矩阵第 7 节场景全部自动化；CI 在 Windows/Linux 通过，失败能定位阶段，覆盖率门槛和离线产物 hash 均纳入发布门禁。

### P2-01：UI 单体和 CSS 规模过大

- **现象**：LootForgeApp.tsx 约 1441 行，CSS 约 652 个物理行；主组件同时承担加载、状态、筛选、批量规则、持久化、导入导出和渲染，存在 4 处 exhaustive-deps 抑制。
- **影响**：职责耦合、隐式 effect 依赖和重复样式增加回归与审查成本，修复 P0 时更容易引入相邻行为变化。
- **证据**：主组件入口和逻辑集中见 [LootForgeApp.tsx#L1-L20](../web/src/ui/LootForgeApp.tsx#L1)；样式集中见 [globals.css#L1-L20](../web/app/globals.css#L1)。
- **建议**：拆分目录/筛选、批量、导入导出、storage hook 和纯展示组件，逐步消除 exhaustive-deps 抑制并为每个服务补契约测试。
- **验收**：模块边界有独立测试；依赖抑制逐项消除或记录理由；拆分后 npm run check、P0 测试和交互行为不回归。

### P2-02：全量物品重建与同步序列化

- **现象**：allItems 依赖 stateMap，任一状态切换都会重建 catalog/custom 合并结果；scope、category、drawer、统计还会反复扫描约 16,571 项，每次 workspace 变化又同步保存。
- **影响**：单项切换和低端设备上的筛选可能出现卡顿，批量预览的计算和保存峰值会放大。
- **证据**：全量合并与筛选见 [LootForgeApp.tsx#L301-L464](../web/src/ui/LootForgeApp.tsx#L301)；后续扫描见 [LootForgeApp.tsx#L557-L592](../web/src/ui/LootForgeApp.tsx#L557)。
- **建议**：预构建静态 item/source/category 索引，动态状态只保存 ID 集合；scope 使用反向索引，重计算放入 worker 或分片，并加入性能基准。
- **验收**：记录 16,571 项单项切换、范围切换、批量预览和保存延迟基线；v1.0.4 不得出现明显回归，长任务不阻塞主线程。

### P2-03：catalog validator 不完整，SHA-256 不等于来源真实性

- **现象**：校验覆盖结构、统计、悬空引用和 hash，但未严格检查 category、字符串/source-boss 双向关系；generatedAt/catalogVersion 不进 hash，未来日期 override 可能压过内置目录。
- **影响**：自洽的伪造或不完整目录仍可能通过，hash 只能证明内容内部一致，不能证明上游来源可信。
- **证据**：validator 与 hash 逻辑见 [catalog.ts#L102-L138](../web/src/storage/catalog.ts#L102)；目录选择与 override 入口见 [storage/catalog.ts#L28-L45](../web/src/storage/catalog.ts#L28)。
- **建议**：使用 schema 枚举和双向关系校验，记录来源、签名/信任级别与 override 生命周期，明确时间覆盖策略，区分自洽 hash 与来源认证。
- **验收**：坏 category、坏字符串、单向 source、未来 generatedAt、hash 自洽但来源不可信的样本分别被拒绝或标记；内置、override、回滚策略有测试。

### P2-04：WorkspaceFilters 与文档功能漂移

- **现象**：WorkspaceFilters 和 DEFAULT_FILTERS 定义 query、categories、qualities、slots、itemLevel、stateView，但 UI 不消费 workspace.filters，实际筛选主要在组件本地 state。
- **影响**：状态导出/恢复与界面筛选可能不一致，README 声称的多维筛选没有对应持久化契约。
- **证据**：类型定义见 [types.ts#L140-L148](../web/src/domain/types.ts#L140)；默认值与 UI 入口见 [constants.ts#L19-L28](../web/src/domain/constants.ts#L19)、[LootForgeApp.tsx#L301-L464](../web/src/ui/LootForgeApp.tsx#L301)。
- **建议**：选择删除死模型并修正文档，或让 UI 使用并持久化该模型；筛选字段、URL/备份和迁移规则只保留一套权威语义。
- **验收**：产品选择落地后，测试筛选、刷新、备份、导入和多维组合；README 与实际功能一致，不再保留未消费字段。

### P2-05：工程化与跨平台构建风险

- **现象**：仓库无 CI；build-offline.mjs 用 Windows 反斜杠字符串判断路径，POSIX 不具备同等边界语义；生产依赖 vinext beta，缺少升级策略。
- **影响**：本地 Windows 通过不代表 Linux/macOS 可重复，路径可能误判，beta 升级可能改变产物或运行时。
- **证据**：构建脚本见 [build-offline.mjs#L15-L19](../web/scripts/build-offline.mjs#L15)；依赖版本见 [package.json#L35-L43](../web/package.json#L35)。
- **建议**：增加 Windows/Linux Actions，统一执行 typecheck、lint、test、build、offline、hash 和无 diff 检查；使用 path.relative 等跨平台边界判断，锁定 beta 升级窗口和回滚产物。
- **验收**：两平台 CI 全过；offline HTML 结构、catalog hash、尺寸和脚本语法一致；依赖升级有 lockfile、E2E、产物基线和回滚记录。

### P3-01：备份/datapack 先读全文后校验大小

- **现象**：backup 和 data pack 导入先 file.text()，之后才在解析层用 TextEncoder 判断字节上限。
- **影响**：超大或恶意文件先完整进入内存，仍可能造成峰值和 UI 卡顿。
- **证据**：UI 读取见 [LootForgeApp.tsx#L796-L827](../web/src/ui/LootForgeApp.tsx#L796)；二次限制见 [workspace.ts#L34-L38](../web/src/storage/workspace.ts#L34) 和 [catalog.ts#L97-L100](../web/src/storage/catalog.ts#L97)。
- **建议**：先检查 File.size，再读取文本；必要时分块/流式处理，共享上限常量，解析层保留二次保护。
- **验收**：超限文件在 file.text() 前被拒绝；边界、UTF-8、异常文件和主线程不阻塞均有测试，workspace 不改变。

### P3-02：reduced-motion 只关闭 transition

- **现象**：prefers-reduced-motion 规则关闭 transition，却没有关闭 animation、keyframes 和 animation-delay。
- **影响**：需要减少动效的用户仍可能看到闪烁、浮动或关键帧动画。
- **证据**：规则见 [globals.css#L325](../web/app/globals.css#L325)。
- **建议**：同时覆盖 animation、animation-delay、scroll behavior 和关键帧播放，保留不影响信息理解的静态状态。
- **验收**：Playwright/人工检查 modal、toast、按钮、loading；reduce 模式下 transition/animation 均停止且页面仍可操作。

### P3-03：版本标签硬编码且命名不一致

- **现象**：UI 显示 Data.丝路风雨，目录和 README 使用丝路风语；README 仍有 v1.0.0 指纹示例，运行时版本已为 1.0.3。
- **影响**：用户看到的产品版本、数据版本和导出指纹不一致，反馈难以定位。
- **证据**：UI 标签见 [LootForgeApp.tsx#L173-L178](../web/src/ui/LootForgeApp.tsx#L173)；版本常量见 [constants.ts#L3-L8](../web/src/domain/constants.ts#L3)；README 见 [README.md#L9-L25](../README.md#L9)、[README.md#L115-L123](../README.md#L115)。
- **建议**：产品版本、catalogVersion、等级显示名、README 示例和指纹来自单一 metadata module/生成文件，构建时扫描旧版本与旧名称。
- **验收**：修改版本或名称后 UI、manifest、离线页、README 和指纹由同一检查通过；唯一命名或兼容别名有产品确认。
