## 2. 核心问题修复与代码级落地明细

### 2.1 【P0-01】初始化失败只读降级保护，严禁覆盖 localStorage
- **问题根因**：`LootForgeApp.tsx` 在 `initialize()` 捕获异常后依然设置了 `setHydrated(true)`，触发保存 Effect 将空工作区写入存储，破坏用户已有配置。
- **修复方案**：
  1. 提取生产级生命周期控制器 `handleWorkspaceInitialization(catalogVersion, onNotify)`。
  2. 当 `loadWorkspace` 抛出异常时，控制器捕获并返回 `{ workspace: createInitialWorkspace(catalogVersion), persistenceEnabled: false }`，同时触发标准错误通知。
  3. `LootForgeApp.tsx` 的 `initialize()` 直接调用 `handleWorkspaceInitialization`，并在 `executeDebouncedSave` 中严格执行 `if (!hydrated || !persistenceEnabled) return false;` 守卫，**完全阻断回写保存**。
- **代码位置**：
  - [workspace.ts#L68-L86](../web/src/storage/workspace.ts#L68-L86)
  - [LootForgeApp.tsx#L186-L227](../web/src/ui/LootForgeApp.tsx#L186-L227)
- **测试覆盖**：
  - `workspace-lifecycle.test.ts` -> `executes handleWorkspaceInitialization on corrupted data: disables persistence, protects original data, and triggers notification`：直接调用生产控制器，验证 `persistenceEnabled === false`、原存储数据未受任何修改，且 `executeDebouncedSave` 拒绝保存。

---

### 2.2 【P0-02】提取共享领域命令，彻底根除“幽灵导出”与界面不可见 Bug
- **问题根因**：`buildCatalogItems` 自动注入 40 项默认项并赋予 `sources: []`，导致 `catalogIdSet` 包含了它们。用户点击移除自定义时，`stateMap` 中的状态未被清除；但界面因其无来源且非 custom 而不可见，造成幽灵状态。
- **修复方案**：
  1. `buildCatalogItems` 还原为纯净的官方掉落目录，不再向静态目录中额外插入无来源的虚拟条目。
  2. 40 项默认项由 `createInitialWorkspace` 注入 `workspace.customItems` 和 `itemStates` 进行初始托管。
  3. 提取纯领域函数 `removeCustomItemFromWorkspace(workspace, id)`，同时清理 `stateMap`、`customItems` 和 `customOverrides`。
  4. UI 的 `removeCustomOverride` 与自动化测试**统一调用该共享领域函数**（UI 调用位于第 693 行），确保实现逻辑完全一致。
- **代码位置**：
  - [catalog/index.ts#L60-L62](../web/src/catalog/index.ts#L60-L62)
  - [state.ts#L124-L133](../web/src/domain/state.ts#L124-L133)
  - [LootForgeApp.tsx#L691-L694](../web/src/ui/LootForgeApp.tsx#L691-L694)
- **测试覆盖**：
  - `workspace-lifecycle.test.ts` -> `it.each(allDefaultItems)`：对 40 项默认物品逐项调用 `removeCustomItemFromWorkspace` 并断言 `combined.text`、`sell.text`、`pickup.text` 绝无残留。

### 2.3 【P2 业务语义修复】解绑 `systemSeed` 批量阻断，理顺 8 个官方物品管理
- **问题根因**：官方 254 个副本中实际存在 8 个特效武器/道具（3 项 `equipment`、5 项 `pet`）。原代码批量操作写了 `&& !item.systemSeed`，导致用户移出自定义后，这 8 个物品仍无法被批量操作。
- **修复方案**：
  1. 批量操作（`applyCategoryDirectAction`、`applyScopePreset`）的排除条件调整为 `!item.customOverride && !item.historical`。
  2. 用户保留自定义（`customOverride`）时受到保护；一旦点击“恢复官方批量管理”移出自定义，物品即可正常参与所属分类/副本的批量操作。
  3. `systemSeed` 仅作为界面辅助徽标展示。
  4. 将 `createCategoryActionRules` 与 `createEquipmentBulkRules` 下沉到 `domain/state.ts`。
- **代码位置**：
  - [state.ts#L154-L193](../web/src/domain/state.ts#L154-L193)
  - [LootForgeApp.tsx#L575-L652](../web/src/ui/LootForgeApp.tsx#L575-L652)
- **测试覆盖**：
  - `workspace-lifecycle.test.ts` -> `it.each(official8CatalogItems)`：直接从 `catalog.std.json` 动态查找并断言 8 项官方物品（3 项 `equipment` + 5 项 `pet`）在移出自定义后响应批量规则。

### 2.4 【P1-04】损坏数据隔离分支准确提示与保存异常 UI 告警控制器
- **问题根因**：隔离逻辑在 `setItem` 异常时未区分分支；`saveWorkspace` 失败时仅输出控制台日志，UI 缺乏统一的告警联动机制。
- **修复方案**：
  1. `loadWorkspace` 增加 `quarantined` 布尔标记：
     - 成功写入隔离键：提示“已自动隔离备份至 `${quarantineKey}`”；
     - 存储写满/写入失败：准确提示“隔离备份写入失败，原存储数据仍保留”。
  2. 提取 `executeDebouncedSave(workspace, persistenceEnabled, hydrated, onNotify)`：
     - 执行 `saveWorkspace`，捕获异常并返回布尔值；
     - 失败时通过 `onNotify` 触发准确的 Toast 消息：`'工作区保存失败，请检查浏览器存储空间或隐私权限设置。'`。
  3. `LootForgeApp.tsx` 的防抖保存 Effect 直接调用 `executeDebouncedSave`。
- **代码位置**：
  - [workspace.ts#L24-L101](../web/src/storage/workspace.ts#L24-L101)
  - [LootForgeApp.tsx#L231-L240](../web/src/ui/LootForgeApp.tsx#L231-L240)
- **测试覆盖**：
  - `workspace-lifecycle.test.ts` -> `accurately reports backup failure when quarantine setItem throws`
  - `workspace-lifecycle.test.ts` -> `safely catches errors and returns false in saveWorkspace on storage failure`
  - `workspace-lifecycle.test.ts` -> `executes executeDebouncedSave on storage failure: returns false and triggers exact error notification`（测试断言真实生产控制器与精确 Toast 文本）

### 2.5 【P2-05】离线打包跨平台相对路径实现
- **问题根因**：`build-offline.mjs` 原先硬编码了 Windows 反斜杠 `\\`，在 POSIX 环境下会报错。
- **修复方案**：
  - 使用标准 `path.relative` 判定资源安全边界：
    ```javascript
    const rel = relative(TEMP_DIR, targetPath);
    if (rel.startsWith('..') || resolve(TEMP_DIR, rel) !== targetPath) {
      throw new Error(`Unsafe asset path: ${reference}`);
    }
    ```
- **代码位置**：
  - [build-offline.mjs#L15-L21](../web/scripts/build-offline.mjs#L15-L21)
